# Centro Ferretero El Pico — Tienda web

Tienda en línea de Centro Ferretero El Pico (Caracas). Next.js (App Router) + TypeScript + Tailwind CSS, publicada en Vercel.
Dos personas trabajan en paralelo, cada una con su propia sesión de Claude Code. La consistencia visual es la prioridad número uno.

Guía visual completa: @docs/guia-de-estilo.md
Contrato de datos de productos: @docs/datos.md
Búsqueda inteligente, relacionados y "Te puede interesar": @docs/recomendaciones.md
Eventos para análisis (qué se registra, privacidad, consultas SQL): docs/eventos.md
Cuentas: borrar, corregir o ver los datos de un cliente (tareas a mano en Neon): docs/cuentas.md
Fórmulas de las calculadoras de proyectos: docs/FORMULAS.md
Next.js 16 (APIs distintas a las que conoces; consulta `node_modules/next/dist/docs/`): @AGENTS.md

## Fase actual del proyecto
- Fase 1: catálogo por categorías con precios. El carrito NO cobra: arma un mensaje y redirige a WhatsApp para cerrar la venta.
- No hay inventario ni existencias en esta fase. No mostrar "disponible/agotado".
- **Pendiente (persona A con persona B): agrupar por color o modelo.** Hay 123 nombres repetidos en una misma categoría (321 productos) que solo cambian en la descripción de Saint (ej. 10 "Collet deco plus pintura 1/4 gal": Amarillo primavera, Coral, Negro…). Propuesta: mismo nombre + marca + subcategoría y distinta descripción → UNA tarjeta ("· 10 colores") con un selector como el de medidas (`lib/agrupaciones.ts`, `CompraConVariantes`). No se hace hasta que persona B lo apruebe.
- **Trabajo pendiente (persona A):** códigos de las calculadoras por revisar con persona B (en `docs/pendiente-buscador-servidor.md`). El buscador desde el servidor ya está hecho (2026-10-28): ya se pueden conectar más categorías de Saint.
- **`BETTER_AUTH_SECRET` es OBLIGATORIA en `.env.local`** (en esta y en cualquier computadora; ya no hay respaldo con `AUTH_SECRET`). Genérala como dice `.env.example`. Vercel ya la tiene (Production y Preview).

## Comandos
- `npm run dev` — servidor local en http://localhost:3000
- `npm run build` — debe pasar sin errores antes de cada commit
- `npm run lint` — debe pasar sin errores antes de cada commit
- `npm test` — pruebas de `lib/` con Vitest (búsqueda, relacionados, perfil, velocidad con 2000 productos); deben pasar antes de cada commit
- Verificación completa: `lint` + `test` + `build` (que también chequea tipos). La UI no tiene pruebas automáticas.
- `npm run db:generate` — después de cambiar `lib/db/esquema.ts`: escribe la migración SQL en `drizzle/` (sin conexión). Se sube al repo.
- `npm run db:migrate` — aplica las migraciones pendientes a la base de Neon de `DATABASE_URL_UNPOOLED` (en tu computadora, la rama `dev` de Neon). Después de un `git pull` que traiga migraciones nuevas, córrelo.

## Cuentas, pedidos y eventos (cómo funciona)
Resumen para persona B y cualquier sesión nueva. Detalle: `lib/auth.ts`, `lib/cuenta.ts`, `docs/eventos.md`, `docs/cuentas.md`.
- **Dónde vive:** Neon (Postgres), NUNCA el SQL Server de la tienda. Conexión en `lib/db/` (Drizzle por HTTP, con reintentos). Dos ramas de Neon: **`dev`** (`ep-little-cell…`, la de `.env.local` en TODAS las computadoras) y **`main`** (`ep-cool-fire…`, producción, la de Vercel). Todas las tablas en `lib/db/esquema.ts`.
- **Migraciones:** cambias `esquema.ts` → `npm run db:generate` (SQL en `drizzle/`, se sube) → `npm run db:migrate` en dev → pruebas → el dueño la aplica en producción poniendo un momento la conexión directa de `main` en `DATABASE_URL_UNPOOLED` y corriendo `db:migrate` (NUNCA pegando el SQL a mano: quedaría sin registrar). Se sube a `main` solo después. Al traer `main` con migraciones nuevas: `npm run db:migrate`.
- **Cuentas (Better Auth):** correo + contraseña (cifrada con scrypt, correo confirmado obligatorio; correos por Resend en `lib/correo.ts`) o Google. Tablas `user`, `session`, `account`, `verification`, `rate_limit` (de la librería) y `perfil` (datos para la factura: tipo, nombre, cédula/RIF, teléfono). Límite de intentos por correo+IP e IP (`lib/limiteIntentos.ts`, claves con HMAC). El servidor entra por `lib/cuenta.ts`; el navegador por `lib/authCliente.ts`. Toda tabla con `user_id` lleva `onDelete: "cascade"` (borrar la cuenta borra todo: `docs/cuentas.md`).
- **Carrito, favoritos y direcciones viajan con la cuenta** (`components/cuenta/SincronizarCuenta.tsx`, en el layout): siguen en `localStorage` como siempre (`useCarrito`, `useFavoritos`, `useDirecciones` no cambian) y se copian a la cuenta (`carrito_item`, `favorito`, `direccion`) medio segundo después de cada cambio. Al ENTRAR se juntan (carrito: cantidad mayor; favoritos: todos; direcciones: sin duplicar) con `lib/mezclaCuenta.ts`; después manda la cuenta; al SALIR se vacían del navegador. Lo que se agrega mientras carga o justo antes de recargar no se pierde (`el-pico:cuenta-pendiente`).
- **Pedidos** (fase 5, `lib/pedidos/`): al tocar "Enviar pedido por WhatsApp" (`FormularioPedido` → `components/pedidos/usePedidoEnCuenta.tsx`), WhatsApp se abre SIEMPRE; en segundo plano, con cuenta, `POST /api/pedidos` guarda `pedido` + `pedido_item` con los precios del catálogo y la tasa BCV de ESE instante (`precio_verificado = false` si Saint no respondió). El carrito NO guarda tasa. "Mis pedidos" en `/mi-cuenta`, `/mi-cuenta/pedidos` y el detalle con "Volver a pedir". Primer pedido sin datos para la factura: `VentanaPrimerPedido` los ofrece sin obligar.
- **Eventos para análisis** (fase 4, `lib/eventos/`): producto visto, categoría vista, búsqueda, carrito, favorito y pedido enviado (uno por producto, con `pedido_codigo` común). Para registrar: `registrarEvento()` de `lib/eventos/cliente.ts` o `<RegistrarEvento evento={…} />`; nada más. Se mandan juntos con `sendBeacon` a `/api/eventos`, que responde al instante y guarda con `after()`. Cookie anónima `el-pico-visitante` (UUID, 1 año, se cambia al cerrar sesión; `visitante_cuenta` la une a la cuenta al entrar). Filtra robots, límite 300/h por visitante y 3.000/h por red; 12 meses en detalle y luego resúmenes mensuales para siempre.
- **Reglas de privacidad (no romperlas):** en eventos nunca IP, navegador, nombre, correo ni teléfono; búsquedas que parecen correo/teléfono/cédula no se guardan; las IP solo como HMAC para los límites; nada de cookies de publicidad. Si cambias qué se guarda, actualiza `/privacidad`.
- **Líneas en páginas de persona B que no se quitan:** `<RegistrarEvento>` en producto y categoría; en `FormularioPedido`, `usePedidoEnCuenta(...)` (de donde salen también `items`, `confirmando`, `preciosPorConfirmar` y `aviso`), `{ventana}`, `{aviso}` junto al botón, el "confirmando precios…" de `faltantes` y el `onClick` del botón de WhatsApp (`alEnviar`); `preciosPorConfirmar` en `DatosPedido`/`armarMensajeFinal`; los exports extra de `almacenDirecciones.ts`.
- **Precios al enviar:** son los precios REALES de venta. Al abrir `/finalizar-pedido`, `usePedidoEnCuenta` le pregunta a Saint el precio actual de cada producto (`POST /api/precios-al-dia` → `preciosAlDia`); el botón espera ("Confirmando precios…", normalmente 1,5–2,5 s, máx. 5 s). Si cambió, se corrige y se avisa (`AvisoPrecios`); si ya no está a la venta, se quita y se avisa; si Saint no responde, se envía igual con los precios que se tenían y el mensaje dice "Precios por confirmar". El pedido guardado toma el precio de Saint de ese instante (`precio_verificado = false` si no se pudo).
- **Probar:** siempre contra la rama `dev` (`npm run build` + `npx next start`; con OneDrive, si `.next` queda bloqueado, borra la carpeta que diga el error y reintenta). Las pruebas de `lib/` no tocan la base de datos.

## Arquitectura
- `lib/catalogo.ts` importa `server-only`: solo se usa en Server Components. Los componentes cliente (`"use client"`) reciben los productos por props.
- `lib/catalogo.ts` trae TODO de Saint (`lib/saint.ts`), categoría por categoría (`&categoria=1758`; la más grande ocupa ~0,8 MB de los 2 MB que acepta la caché de Next): la página de una categoría usa SOLO la suya y el índice (buscador, "Te puede interesar", carrito, favoritos, destacados, página de producto) JUNTA las 10 guardadas; si una falla, las demás siguen (`completo: false`). "Comprados juntos" todavía no tiene fuente (`getCompradosJuntos()` devuelve `[]`; ver Pendiente arriba).
- Next 16: `params` es una `Promise` (`const { slug } = await params`) y las páginas se tipan con los helpers globales `PageProps<"/ruta">` / `LayoutProps<"/">`.
- Carrito: `ProveedorCarrito` envuelve todo en `app/layout.tsx` y renderiza `PanelCarrito` (solo desde 768px). **En el teléfono el carrito es la página `/carrito`:** `abrir()` de `useCarrito()` lleva ahí en vez de abrir el panel. El estado vive en `localStorage` (clave `el-pico:carrito`) vía `useSyncExternalStore` en `almacenCarrito.ts`, sincronizado entre pestañas. Desde componentes cliente usa el hook `useCarrito()`.
- Precios en USD como `number`; para mostrarlos, `Precio` (o `formatearPrecio` en texto plano, ej. el mensaje de WhatsApp).
- Nombre de producto para mostrar: `tituloProducto()` en `lib/formato.ts` ("TALADRO PERCUTOR 1/2\" 650W" + PROTEK → "Taladro percutor Protek 1/2\" 650W"). Lo usan `ProductCard`, el carrito y la página de producto; nunca muestres `producto.nombre` en MAYÚSCULAS. El mensaje de WhatsApp sí usa el nombre tal como viene del sistema.
- Búsqueda y recomendaciones (`lib/recomendaciones/`): los algoritmos RECIBEN la lista de productos (nunca importan `lib/catalogo.ts`) y funcionan igual en servidor y navegador. Los datos llegan por `getIndiceProductos()`, `getMasVendidos()` y `getCompradosJuntos()` de `lib/catalogo.ts`; al conectar el SQL solo cambia ese archivo. Todo texto se compara con `palabrasClave()` (sin acentos, singular, medidas y sinónimos unificados); no compares nombres de producto a mano. Sinónimos, complementarios y consumibles se editan en `datos/*.json`, nunca en el código. **El navegador NUNCA descarga el catálogo** (con ~30.000 productos serían 6,6 MB): búsqueda, sugerencias y "Te puede interesar" usan el índice ÚNICO del servidor de `lib/indiceServidor.ts` (`indice()` lo espera, para `/buscar`; `indiceSiEstaListo()` no espera y, si falta, lo arma en segundo plano con `after()`; nada de cron jobs). Desde el navegador se pregunta a `/api/sugerencias?q=` (header), `POST /api/te-puede-interesar` y `POST /api/favoritos`, que mandan solo los campos que se muestran (incluida la `descripcion` de Saint, que es corta). El buscador y el `?q=` de la categoría buscan también en la descripción ("azul", "01-755P"). Ninguna de esas rutas registra eventos: la búsqueda se registra en `/buscar`. `getIndiceConEstado()` devuelve la MISMA lista mientras nada cambie: así `crearIndice`/`prepararCatalogo` (que solo reutilizan su trabajo si reciben la misma lista) no rehacen la preparación en cada visita.
- `Producto.ventas?` (opcional) ordena los "más vendidos"; Saint todavía no lo manda. Mientras tanto, el inicio usa `getProductosDestacados(seccion)`: los códigos de `datos/destacados.json` (editable sin programar: "recomendados", "te-puede-interesar" y un carrusel por categoría) y, si faltan, una mezcla automática del día (un producto por subcategoría, `lib/destacados.ts`). "Te puede interesar" del inicio recibe `getProductosDestacados("te-puede-interesar")` y `TePuedeInteresar` lo personaliza con el servidor.
- Perfil del cliente: `localStorage` clave `el-pico:perfil` (`lib/recomendaciones/almacenPerfil.ts`, siempre con try/catch). Solo IDs de producto, términos de búsqueda y fechas; NUNCA datos personales. Señales: `whatsapp` (8), `carrito` (4), `visto` (2), `busqueda` (1), `compra` (8, para el historial del SQL). Ya se anotan solas en `agregar()`, en el botón "Enviar pedido por WhatsApp" de `FormularioPedido` (todo pedido pasa por `/finalizar-pedido`) y en `/buscar`. Si creas otro punto de envío a WhatsApp, anota `registrarSenales(items.map((i) => ({ tipo: "whatsapp", id: i.producto.id })))`. En la página de producto van `<RegistrarSenal senales={[{ tipo: "visto", id }]} />` y `<ProductosRelacionados producto={producto} />` (reemplaza el carrusel de "misma categoría").
- Datos de la tienda física: siempre desde `TIENDA`/`APPS_MAPAS` de `lib/tienda.ts`; nunca escribas la dirección a mano en un componente. El teléfono AÚN NO está confirmado: no lo muestres hasta que persona A lo confirme. El horario ya está confirmado y vive en `lib/horario.ts` (nunca lo escribas a mano). El mapa es un iframe de OpenStreetMap (sin clave ni costo) con el pin propio encima; el selector de apps es un modal en portal.
- Imágenes: los productos de Saint todavía no traen foto (`imagen: null`): la tarjeta muestra el ícono de su subcategoría (`iconoDeProducto` en `components/icons/pico/porCategoria.ts`, con íconos propios para algunas subcategorías). Las fotos sueltas de `lib/agrupaciones.ts` son la excepción. `ImagenProducto` usa `object-contain` con margen proporcional (`p-[7%]`), así se ve bien desde 40px (sugerencias) hasta la página de producto.
- Ancho: `Contenedor` usa `max-w-pagina` (1760px con el margen incluido, token `--container-pagina`) y `px-pagina` (margen fluido `--margen-pagina: clamp(16px, 4vw, 48px)`), ambos definidos SOLO en `app/globals.css`; la barra de categorías (`EnlacesCategorias`) usa el mismo ancho. Las filas que se salen hasta el borde en móvil usan `-mx-[var(--margen-pagina)]`, no `-mx-4`.
- Páginas interiores en franjas: no se envuelve toda la página en un solo `Contenedor`; se apilan franjas a todo el ancho con `Franja` (`tono="gris"` o `"blanco"`, alternando; `decorada` agrega un velo azul claro y las montañas del logo) y el contenido va dentro. Toda página interior empieza con `EncabezadoPagina` (franja azul de borde a borde con ruta de navegación, acento rojo y el `h1`); sin `titulo` queda delgada, solo con la ruta (página de producto y opiniones). **La página principal NO usa franjas:** volvió a como estaba el 2026-10-12 (todo dentro de un `Contenedor`) para empezarla de nuevo; ver el registro.
- Banner de calculadoras: en el inicio va `components/inicio/BannerCalculadorasInicio.tsx`: una TIRA delgada en el mismo azul marino que los demás banners (clase `.tira-plano`, de `pico-azul` a `pico-azul-oscuro`; también la usa el encabezado de `/calculadoras`) con cuadrícula de tiza de plano de obra, "¿Cuánto material TE HACE FALTA?" con subrayado `amarillo-obra`, al centro la libreta amarilla de "La lista" (más alta que la tira, sobresale como pegada encima; sus cantidades salen de `calcularBloques`, nunca a mano; palomitas rojas en bucle con `.libreta-check`, quietas y marcadas con reducir movimiento) y el botón blanco con letra roja "Calcular mi obra". En las categorías construccion, pinturas y tornilleria va `components/calculadoras/BannerCalculadoras.tsx` (franja blanca de borde a borde con tres fotos de `public/proyectos/`; `CON_CALCULADORAS` en la página de categoría). La ruta está en `components/calculadoras/rutas.ts`. Carruseles: 6 tarjetas desde 1536px; `GrillaProductos`: 5 columnas desde 1536px.
- Buscador: `BuscadorConSugerencias` usa `sugerirCorrigiendo()` (en `lib/recomendaciones/busqueda.ts`): si lo escrito no encuentra nada, corrige la ortografía con `quisoDecir()` y muestra "Mostrando resultados para …".
- Tasa BCV: NUNCA va fija en el código. `getTasaBCV()` consulta `TASA_API_URL` (ver `.env.example`; si falla, usa la tasa que trae Saint), que responde `{ tasa: number, fecha?: string }` (la fecha es opcional). **El endpoint ya existe** y su URL (con clave) vive SOLO en `.env.local` y en Vercel; sin URL o si falla, la píldora muestra un guion. `useTasaBCV()` guarda el último valor en `localStorage` (clave `el-pico:tasa-bcv`) y lo muestra si la consulta falla. La píldora (`PildoraTasa`) crece con la cifra y nunca la corta; formato `es-VE` con 2 decimales. A la vista muestra SOLO el monto ("886,23"): la moneda la dice la bola roja "Bs" (el lector de pantalla oye "Bs." igual).
- Calculadoras de proyectos: cada una es un objeto `Calculadora` (slug, `imagen` de su tarjeta, campos, opciones, herramientas, `calcular()` y explicación) en su archivo de `lib/calculadoras/`. **Para agregar una:** crea el archivo y súmala a `CALCULADORAS` en `registro.ts`; los componentes no se tocan. `calcular()` es una función pura que devuelve materiales ya redondeados HACIA ARRIBA a unidades de venta. Los coeficientes NUNCA van en el código de la fórmula: van en `constantes.ts` y se documentan en `docs/FORMULAS.md` con un ejemplo que también es caso de prueba. Los productos del resumen se piden al catálogo por código (`MATERIALES[...].productoId` + `getProducto`); un material sin producto (o con código que ya no existe) sale igual, con "Consultar disponibilidad" (no hay stock en esta fase). "Agregar todo al carrito" llama a `agregar()` de `useCarrito()` por cada producto: no hay otra lógica de carrito. El equivalente en Bs sale solo cuando `useTasaBCV()` devuelve tasa.
- Imágenes remotas: cuando la API entregue URLs, agrega el dominio a `images.remotePatterns` en `next.config.ts`.
- `Producto.descripcion` es opcional: la descripción de Saint (Descrip2), ver `lib/nombresSaint.ts` en Estructura. Se ve bajo el nombre en `ProductCard`, la página de producto (en un grupo de medidas, la de la medida elegida, en `CompraConVariantes`), las sugerencias del buscador, el carrito, "Tu pedido" de finalizar pedido, el detalle de "Mis pedidos" (se guarda en `pedido_item.descripcion`) y el mensaje de WhatsApp (`— AMARILLO PRIMAVERA` / `— Ref. …` tras el nombre). Nunca inventes descripciones.
- Flujo de compra: todo pedido pasa por `/finalizar-pedido` antes de WhatsApp. El cliente elige "¿Cómo retiras?" (Pick-up / Delivery / Flete; con Delivery o Flete elige una de sus direcciones) y "Método de pago" (Divisas, Pago móvil, Transferencia bancaria, Cashea, Zelle, USDT o Pago combinado, que pide marcar al menos dos). El botón de WhatsApp se activa solo con todo elegido y el mensaje lo arma `armarMensajeFinal()` en `components/finalizar-pedido/pedido.ts`.
  - Desde el carrito (`PanelCarrito` → "Finalizar compra"): `/finalizar-pedido`, usa los productos del carrito. El carrito NO se vacía al enviar.
  - "Comprar ahora" (página de producto): `/finalizar-pedido?producto=ID&cantidad=N`, solo ese producto; no toca el carrito.
- Direcciones de entrega: el cliente guarda varias (nombre + descripción corta + punto en el mapa; tipo `Direccion` en `types/cliente.ts`) con `useDirecciones()` de `components/direcciones/almacenDirecciones.ts` (`localStorage` clave `el-pico:direcciones`: la lista y la elegida). No hay dirección principal en el perfil: la elegida en el header ("Entregar en") sale marcada en finalizar pedido, se puede cambiar ahí, y la de finalizar pedido es la que va en el WhatsApp (con enlace a Google Maps). Con sesión, ese almacén se sincroniza con la cuenta (`SincronizarCuenta`, como el carrito: al entrar se juntan sin duplicar —mismo id, o mismo nombre y a menos de 25 m—; al cerrar sesión se borran del navegador) y las pantallas no cambian. El mapa es Leaflet (dependencia `leaflet`) con mosaicos de OpenStreetMap, sin claves; la miniatura de cada dirección son mosaicos sueltos (`MiniMapa`, sin librería).
- Rebranding en TODA la tienda (acordado por persona A y persona B): los tokens `pico-*` de `app/globals.css` tienen los colores del logo nuevo (azul marino #0c2d4e, rojo #c4161c); los `logo-*` son los mismos colores con otro nombre (los usan las páginas de persona B). Para piezas nuevas compartidas, prefiere `pico-*`. Detalle en `docs/guia-de-estilo.md`.

- Letra de toda la tienda: Chakra Petch (definida en `components/producto-detalle/fuentes.ts`, cargada en `app/layout.tsx`; `--font-sans` y `font-titulo` la usan; si no cargara, cae a la letra del sistema). Inter y `fuentePaginas` se quitaron: no pongas clases de fuente en las páginas.
- Controles que se ven más pequeños de 44×44px (migas, botones chicos): agrega la utilidad `area-tactil` (globals.css), que amplía la zona táctil sin cambiar cómo se ven. No en elementos `absolute`/`fixed`.

- Imágenes que se ven al abrir la página (LCP): `ImagenProducto`/`ProductCard` aceptan `prioritario`; `GrillaProductos` lo da solas a las 4 primeras y acepta `titulo` (un h2 oculto para lectores de pantalla, porque las tarjetas son h3).

Estilo: blanca con borde gris arriba, íconos finos en `gris-texto`, nombres cortos sin mayúsculas y la pestaña activa con el ícono blanco en un círculo `pico-azul`. Tocar la pestaña de la página en la que ya estás sube al principio. **El header (logo, tasa, dirección, buscador) solo sale en el teléfono en `RUTAS_CON_HEADER_MOVIL` (`/` y `/buscar`, en `pantallaCompleta.ts`; lo aplica `HeaderSoloInicioMovil` en `app/layout.tsx`)**: las demás páginas empiezan con su `EncabezadoPagina`, que en el teléfono trae una lupa arriba a la derecha que lleva a `/buscar` (prop `lupa`, `true` por defecto; `/buscar` la quita). Los modales que deban tapar la barra usan `z-50` (la barra es `z-42`).
- Páginas de pantalla completa: las rutas de `RUTAS_PANTALLA_COMPLETA` (`components/layout/pantallaCompleta.ts`; hoy `/iniciar-sesion` y `/crear-cuenta`) se muestran sin header, barra de categorías, footer ni barra inferior (`OcultarEnRutas` en `app/layout.tsx`). Cada una debe traer su propia salida ("Volver a la tienda").
- Favoritos: `useFavoritos()` de `components/favoritos/almacenFavoritos.ts` (`localStorage` clave `el-pico:favoritos`, solo códigos de producto, lo último primero, sincronizado entre pestañas). `/favoritos` pide al servidor solo esos productos (`POST /api/favoritos`, máx. 200 códigos; precios al día); lo que ya no existe se QUITA de los favoritos (en la página y, con sesión, en la cuenta: `favoritosVigentes()` de `lib/cuenta.ts`), así el contador del header coincide con la página; si faltó una parte del catálogo (`completo: false`) no se quita nada y avisa en vez de darlos por desaparecidos. El corazón (`BotonFavorito`) va en cada `ProductCard` (esquina de la foto) y como chip "Guardar" en la página de producto. En escritorio, "Favoritos" va en el header entre Calculadoras y Mi cuenta.
- `Precio` tiene la prop opcional `tono="logo"`; hoy da el mismo rojo que el valor por defecto.
- Opiniones (estrellas): tipos en `types/opiniones.ts`; datos por `lib/opiniones.ts` (`getOpiniones`, server-only) y el promedio con `lib/resumirOpiniones.ts` (sirve en cliente y servidor). No hay base de datos de opiniones todavía: devuelve lista vacía (las opiniones FALSAS de prueba se borraron el 2026-10-28; nunca se muestran reseñas inventadas).
- Opiniones que escribe el cliente: sin base de datos se guardan en su navegador (`components/opiniones/almacenOpiniones.ts`) y se suman a las del servidor con `useOpinionesProducto()`. Las estrellas y la sección "Calificaciones" de la página de producto usan `EstrellasProducto` / `CalificacionesProducto` (`components/opiniones/CalificacionesVivas.tsx`) para incluirlas. Cuando exista la base de datos, `FormularioOpinion` debe enviar al servidor en vez de `agregarOpinion()`.
